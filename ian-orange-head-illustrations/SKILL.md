# Ian 橘子头像素文章配图

## 核心定位

为中文文章设计完整配图组：开头封面是 16:9 横版，正文配图是 16:9 横版，结尾总结信息图是 3:4 竖版。目标不是做商业插画、PPT 页面或游戏截图，而是把文章的核心主题、关键认知和全文结论，变成清爽、有创意、可读但不说明书的像素视觉。

默认视觉 IP 是“橘子头”：大头小身、蓬松橙发、简洁像素五官、黑白服装。橘子头必须参与画面的核心动作，不能只是站在旁边当装饰。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：风格 DNA、颜色、文字、禁忌。
- `references/orange-head-ip.md`：橘子头 IP 的形象、性格、动作库和禁忌。
- `references/composition-patterns.md`：结构类型、原创隐喻方法和反复刻规则。
- `references/prompt-template.md`：封面、正文配图和总结信息图的生图提示词模板。
- `references/qa-checklist.md`：生成后检查和迭代规则。
- `assets/orange-head-reference.png`：橘子头角色参考图。生成角色时读取，用于保持身份一致，不照抄参考图的站姿和构图。

## 工作流

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容。提炼：

- 核心观点是什么
- 文章标题或最适合封面表达的核心主题是什么
- 全文最终要让读者记住的结论是什么；读者可以直接照做、判断或带走的 3-5 个模块是什么
- 哪些段落承担认知转折
- 哪些内容适合用图解释
- 哪些地方只适合文字，不需要图

不要平均配图。优先选择“认知锚点”，例如：核心判断、两个断点、输入输出闭环、分流、前后对比、一鱼多吃、承接路径、常见坑、角色状态变化。

### 2. 先出配图策略

如果用户只是说“分析怎么配图 / 思考哪些地方需要配图”，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 橘子头在图里做什么
- 背景如何呼应当前画面
- 建议元素
- 建议中文标注词

完整文章默认 4-8 张，数量包含首张封面和末张总结信息图；中间只为真正需要解释的认知锚点安排正文配图。文章很短时可只做封面与总结图，或加 1 张正文图；长文也不要轻易超过 9 张。用户明确只要正文配图时，不强制添加封面和总结图。

完整文章的 shot list 按以下顺序组织：

1. **封面**：放在文章开头，只表达文章主题和情绪，不承担细节解释。
2. **正文配图**：放在对应段落后，每张只解释一个认知锚点。
3. **总结信息图**：放在文章结尾，用一个中心结论串联 3-5 个模块。每个模块不只写名称，还要说明具体做什么、如何做或判断什么，以及完成后得到什么；底部增加可保存的带走清单或下一步。

每张图额外标明“图像角色：封面 / 正文配图 / 总结信息图”。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，不要停下来等确认；用内置 `image_gen` 每张单独生成。不要把多张图拼在一张里。

先根据图像角色选择 `references/prompt-template.md` 中对应模板。三类图共用以下要求：

- 封面固定为 16:9 横版，正文配图固定为 16:9 横版，结尾总结信息图固定为 3:4 竖版
- 符合当前主题、地点和动作的简洁像素背景；除非用户明确要求纯白底，否则不要让角色悬浮在空白画布中
- 清晰的像素块和阶梯状像素边缘
- 橙色主体、黑白辅助色
- 少量中文像素字体批注
- 足够的视觉呼吸空间
- 橘子头作为核心动作主体
- 禁止 PPT、商业插画、幼稚可爱、复杂架构、左上角类型标题

封面可以出现文章标题，但应把标题作为封面主视觉的一部分，不能写成左上角的类型标签。默认使用用户给出的文章标题；标题过长时，先缩成不改变原意的短标题。封面只建立主题、情绪和记忆点，不罗列正文要点。

总结信息图是“一张图只讲一个核心结构”的受控例外：它仍然只围绕一个全文结论，但允许使用 3-5 个结构化模块。方法、流程和教程类文章中，每个模块至少包含“模块标题 + 具体行动或解释 + 阶段产出”；观点类文章则包含“核心判断 + 必要解释或应用”。底部给出读者应带走的清单、下一步或必要提醒。它应是一张用户离开文章后仍能独立使用的行动卡或知识卡，而不只是文章目录。

总结图中文字优先，插图只负责解释文字。先限制模块数量，再补视觉细节。可以使用统一的信息块、编号、箭头和图标建立层级，但不能堆成长段正文、互不相干的卡片或企业 PPT 页面。为减少角色漂移，优先使用 1 个主橘子头贯穿信息流；需要重复角色时，必须保持发型、脸型、五官和服装一致。

不要复刻过往案例。参考图只提供橘子头的身份锚点，不能直接复用站姿、构图或背景。每次都要从当前文章重新发明一个清楚、有趣且成立的隐喻。

### 4. 检查与迭代

生成后检查 `references/qa-checklist.md`。如果出现以下问题，优先重生成或局部编辑：

- 橘子头只是装饰
- 画面太满
- 太像流程图/PPT
- 中文太多或错字严重
- 左上角出现“常见坑/流程图/系统架构图”等标题
- 画风太幼稚、平滑或不具备像素感
- 背景与当前画面无关、过于空洞或抢走角色焦点
- 封面塞入过多正文要点，或标题不清楚
- 总结信息图遗漏全文主结论、模块超过 5 个，或只有阶段名称而没有具体行动、解释和产出
- 总结信息图离开文章后无法独立使用，底部没有带走清单、下一步或必要提醒

### 5. 保存交付

如果用户在 workspace 内工作，把最终图复制到：

```text
assets/<article-slug>-illustrations/
```

按顺序命名：

```text
01-cover.png
02-topic-name.png
NN-summary.png
```

保留原始生成文件，不要覆盖已有资产，除非用户明确要求替换。

## 输出口径

生成前的策略输出要短而准。生成后的交付要包含：

- 生成了几张
- 每张图的角色和用途
- 保存路径
- 哪些图最稳，哪些图是可选

不要长篇解释风格理论；让图自己说话。

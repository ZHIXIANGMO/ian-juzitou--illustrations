# Prompt Examples

下面这些 prompt 可以直接复制到 Codex 里使用。

## 只做配图规划

```text
Use $ian-orange-head-illustrations 先不要生图。
请分析下面这篇文章哪里值得配图，输出 5 张左右的 shot list。
每张图写清楚：
- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 橘子头在图里做什么
- 建议元素
- 建议中文标注词

<粘贴文章>
```

## 文章正文配图

```text
Use $ian-orange-head-illustrations 把下面这篇文章生成 4 张橘子头像素正文配图。
要求：16:9 横版、背景符合当前画面、橙色主体、清晰像素块、少量中文像素字体批注。
每张图只讲一个核心结构，不要做 PPT 信息图，不要低幼卡通。

<粘贴文章>
```

## 完整文章配图组

```text
Use $ian-orange-head-illustrations 为下面这篇文章生成一组 5 张配图。

- 第 1 张：文章开头封面，只表达主题和情绪
- 第 2-4 张：正文配图，只挑最重要的 3 个认知锚点
- 第 5 张：文章结尾总结信息图，用一个结果承诺串联 3-5 个可执行或可应用模块

封面和正文配图使用 16:9 横版，结尾总结信息图使用 3:4 竖版。全部保持橘子头 IP、符合当前画面的简洁像素背景和橙色视觉中心。

<粘贴文章>
```

## 单独生成文章封面

```text
Use $ian-orange-head-illustrations 为下面这篇文章生成开头封面。
使用 16:9 横版。封面只表达文章主题和情绪，标题放在安静区域，不要罗列正文要点。
橘子头必须参与主题动作，画面不要做成商业海报或 PPT。

<粘贴文章>
```

## 单独生成结尾总结信息图

```text
Use $ian-orange-head-illustrations 为下面这篇文章生成一张结尾总结信息图。
使用 3:4 竖版。
把它做成用户可以保存并独立使用的行动卡或知识卡，而不是文章目录。
先提炼一个结果承诺和 3-5 个模块。方法、流程和教程类文章中，每个模块写清：具体做什么、如何做或判断什么、完成后得到什么；观点类文章写清核心判断和应用。
底部增加读者应带走的清单、下一步或必要提醒。文字是主要信息，插图只负责解释；优先只使用 1 个主橘子头，避免人物身份漂移。
不要复制正文段落，不要超过 5 个模块，不要做企业 PPT 或装饰性卡片拼盘。

<粘贴文章>
```

## 长文配图策略

```text
Use $ian-orange-head-illustrations 给这篇长文做配图策略。
不要平均配图，只挑认知锚点：核心判断、输入输出闭环、前后对比、常见坑、承接路径。
默认 6-8 张，先输出 shot list，不要生成图片。

<粘贴文章>
```

## 单个观点生成一张图

```text
Use $ian-orange-head-illustrations 为这个观点生成一张 16:9 正文配图：

信任不是喊出来的，而是一块证据一块证据铺过去。

画面要清爽、有趣，橘子头必须承担核心动作。
中文标注最多 5 个，短一点。
```

## 工作流主题

```text
Use $ian-orange-head-illustrations 为“把一条原始素材加工成流量、信任、转化三种内容”生成一张图。
不要画正式流程图，不要复刻一鱼多吃旧案例。
请重新发明一个新的低科技隐喻，让橘子头参与核心动作。
```

## 改图：去掉标题

```text
Use $ian-orange-head-illustrations 帮我编辑这张图。
去掉左上角的“Workflow / 流程图”标题和下划线，其他内容保持不变。
不要新增任何文字或物件。
```

## 改图：增强橘子头参与感

```text
Use $ian-orange-head-illustrations 这张图方向对，但橘子头有点像装饰。
请保持核心意思不变，重生成一版：让橘子头成为真正推动结构运转的人。
保持符合当前画面的简洁背景、橙色主体、清晰像素风和少字。
```

## 生成一组风格样片

```text
Use $ian-orange-head-illustrations 输出 5 个不同主题的橘子头正文配图效果。
主题分别覆盖：信息过载、产品验证、内容复利、一人公司、信任建立。
每张单独生成，不要拼成一张。
```
